# usb-whitelist-guard

Blocks USB devices that are not on an allowlist. A background **monitor** watches for newly connected USB devices, checks each one's VID/PID/serial against the allowlist and disables unknown devices immediately. A desktop **GUI** manages the allowlist and shows the event history.

Works on Windows and Linux from one Python codebase.

Handling a single device:

```mermaid
sequenceDiagram
    participant OS as OS (WMI / udev)
    participant W as DeviceWatcher
    participant G as GuardService
    participant P as FailSecurePolicy
    participant DB as SQLite
    participant B as DeviceBlocker

    OS->>W: new USB device event
    W->>G: UsbDevice(vid, pid, serial, system_path)
    G->>P: evaluate(device)
    P->>DB: allowlist entries for vid:pid
    alt matching entry
        P-->>G: ALLOW "on allowlist"
        G->>B: unblock(device)
    else no match
        P-->>G: BLOCK "not on allowlist"
        G->>B: block(device)
    else database / policy error
        P-->>G: BLOCK "policy error: …"
        G->>B: block(device)
    end
    G->>DB: record DeviceEvent(timestamp, device id, decision, reason)
```

### Device detection

| | Windows | Linux |
|---|---|---|
| Source | WMI query `__InstanceCreationEvent WITHIN 1` on `Win32_PnPEntity` with `PNPDeviceID LIKE 'USB\VID_%'` | udev netlink monitor, `subsystem=usb`, `device_type=usb_device`, action `add` |
| Latency | up to ~1 s (WMI polls internally) | immediate (kernel pushes the event) |
| Device ID | parsed from `USB\VID_xxxx&PID_xxxx\<serial>` | sysfs attributes `idVendor`, `idProduct`, `serial` |
| Blocking | `Disable-PnpDevice` (PowerShell) | write `0` to `/sys/bus/usb/devices/<dev>/authorized` |

On Windows, an instance ID whose last segment contains `&` is generated by Windows and is not a real serial number, so the device's serial is treated as unknown.

### Allowlist matching

Every entry has a VID and PID (4 hex digits) and an optional serial number:

- **with a serial**, the entry only allows that one physical device;
- **without a serial** ("any"), it allows every device with that VID:PID.

### First run

When the monitor starts with an empty database (no allowlist entries and no events), it adds every USB device connected at that moment to the allowlist, so your keyboard, mouse and other devices you already use stay allowed. Each entry keeps the device's serial if it has one, and its note says "connected at first run". Once the database has any data, the monitor never does this again. If the database can't be read at startup, nothing is added.

### Connected devices

At startup the monitor also checks every USB device that is already connected, so a device plugged in while the monitor wasn't running is blocked too. After that it re-reads the allowlist every 2 seconds and, when it changes, re-checks the connected devices: removing an entry blocks a matching device that is plugged in, and adding one unblocks it without replugging. Only devices whose decision changed are blocked or unblocked. These checks are skipped while the allowlist can't be read, so a database failure never cuts off the keyboard and mouse in use. On Linux, root hubs are never checked.

### Fail-secure

Every device is blocked when its state can't be checked:

- `FailSecurePolicy` turns any exception during evaluation (e.g. the database is unreachable) into a `BLOCK` verdict.
- If the database can't be opened or migrated at startup, the monitor logs the error and keeps running, so every new device is blocked.
- Failing to block or to record an event is logged and included in the event reason; it doesn't stop the monitor.

## Project layout

A [uv workspace](https://docs.astral.sh/uv/concepts/projects/workspaces/) with three packages:

```
packages/core/   usb-whitelist-guard-core     domain model, policies, services, SQLite storage + Alembic migrations
apps/monitor/    usb-whitelist-guard-monitor  background service: platform watchers and blockers
apps/gui/        usb-whitelist-guard-gui      Tkinter app for the allowlist and event history
```

The core is split into layers:

| Package | Contents |
|---|---|
| `domain` | `DeviceId`, `UsbDevice`, `AllowlistEntry`, `DeviceEvent`, `Decision` / `Verdict`, errors |
| `ports` | protocols: `DeviceWatcher`, `DeviceBlocker`, `AllowlistReader` / `Writer`, `EventSink` / `Reader` |
| `policy` | `AllowlistPolicy`, `FailSecurePolicy` |
| `services` | `GuardService` and first-run seeding (used by the monitor), `AllowlistService` (used by the GUI) |
| `storage` | SQLAlchemy models, repositories, Alembic migrations |

Platform code depends only on the `ports`, so you can add a new OS by implementing `DeviceWatcher` (`connected()` and `watch()`) and `DeviceBlocker` in `apps/monitor/.../platforms/`.

## Installation

Requires Python 3.15+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync --all-packages
```

Platform dependencies are installed automatically: `wmi` (and `pywin32`) on Windows, `pyudev` on Linux. The GUI uses Tkinter from the standard library with the [Sun Valley](https://github.com/rdbende/Sun-Valley-ttk-theme) theme (`sv-ttk`). Some Linux distributions ship Tkinter as a separate package, e.g. `python3-tk`.

## Usage

When run from the repository, both apps need **administrator / root** privileges. The monitor writes to the device stack, and both apps write to the shared database, which by default lives in a system location.

```bash
uv run usb-whitelist-guard-monitor
uv run usb-whitelist-guard-gui
```

The GUI follows the system light/dark setting. Pass `--theme light` or `--theme dark` to override it. Under `sudo` the system setting is root's, not yours.

### Installing on Linux

For everyday use, install the apps system-wide instead of running them from the repository. This needs systemd and uv.

```bash
sudo packaging/linux/install.sh
```

The installer:

- installs both apps with their own Python 3.15 into `/opt/usb-whitelist-guard`, and links the commands into `/usr/local/bin`;
- runs the monitor as the `usb-whitelist-guard-monitor` systemd service, which starts at boot and restarts on failure;
- creates the `usb-whitelist-guard` group, gives it write access to `/var/lib/usb-whitelist-guard`, and adds the user who ran `sudo` to it. Members run the GUI **without sudo** (log out and back in first). Only add users you trust to approve devices;
- adds "USB Whitelist Guard" with its icon to the application menu.

Run it again to upgrade. To remove the apps:

```bash
sudo packaging/linux/uninstall.sh          # keeps the database and the group
sudo packaging/linux/uninstall.sh --purge  # deletes them as well
```

## Requirements

### Functional

- Detect newly connected USB devices in real time (Linux: udev, Windows: WMI).
- Read device VID/PID (and serial if available) and check it against the allowlist.
- Automatically block unknown devices (Linux: sysfs `authorized = 0`, Windows: `Disable-PnpDevice`).
- Log each event with timestamp, device ID and decision.

### Non-functional

- Runs on Linux and Windows from one Python codebase.
- Requires root / administrator privileges.
- Fail-secure: if the allowlist is missing or invalid, unknown devices are blocked.
